Contrato documental versionado

Evolucionar documentos sin exigir una migración instantánea de todo el conjunto.

Problema que resuelve

Cambiar el significado de un campo bajo el mismo nombre produce lectores temporalmente incompatibles.

Analogía

Como una guía de especies por ediciones: cada observación indica con qué edición fue clasificada.

Solución y contrato

Cada documento declara versión; lectores admiten un intervalo explícito y las transformaciones entre versiones son deterministas e idempotentes.

leer(según versión); migrar(de, hacia) deFormaIdempotente()

Cuándo aplicarlo

Úselo ante cambios aditivos o incompatibles. Mantenga pruebas de lectura hacia atrás y hacia delante durante la convivencia.

Ejemplo ejecutable

Ejemplo pedagógico; no es una declaración de conformidad con Core 1.0. El lector selecciona el contrato correcto y migra de forma explícita.

Aplicación móvil todavía usa el formato anterior: Cambiar nombre de campos rompe tabletas que aún no se actualizaron.

Desde la raíz del repositorio, Node.js 22.13 o superior. La instalación requiere acceso al registro de paquetes.

Instalar y comprobar

npm ci --prefix replication
npm test --prefix replication/examples/patterns-r4

Resultado esperado: casos conformes y adversos de los treinta patrones y regresiones PC1 aprobados. El comando indica el conteo vigente. Los fragmentos usan tipos y ayudantes del proyecto completo.

TypeScript

export function contratoVersionado(entrada: Entrada): Resultado {
  const version = numero(entrada, "versionEsquema");
  if (version === 1) return { versionEsquema: 2, especieCodigo: texto(entrada, "codigoEspecie") };
  if (version === 2) return { versionEsquema: 2, especieCodigo: texto(entrada, "especieCodigo") };
  throw new ErrorPatron("SCHEMA_VERSION_UNSUPPORTED", "La versión documental no está soportada");
}

Entrada conforme y resultado esperado

{
  "entrada": {
    "versionEsquema": 1,
    "codigoEspecie": "AV-12"
  },
  "esperado": {
    "versionEsquema": 2,
    "especieCodigo": "AV-12"
  }
}

Entrada adversa y rechazo o abstención esperados

{
  "entrada": {
    "versionEsquema": 3,
    "especieCodigo": "AV-12"
  },
  "codigoError": "SCHEMA_VERSION_UNSUPPORTED"
}

Alternativa más sencilla

Cambio aditivo compatible. Preferirlo si conserva significado y lectores existentes.

Cuándo no usarlo

No adopte Contrato documental versionado si el problema no fue observado o una alternativa más simple satisface el contrato.

Costo que debe medir

Mida documentos por versión, fallos de conversión y consumidores antiguos. Se relaciona con Catálogo versionado y Publicación por versión.

Límite de esta demostración

La conversión local no demuestra migración de toda una colección.

Práctica guiada

Lea documentos de tres versiones, migre dos veces la misma muestra y compare huellas.

  1. Prepare un caso válido.
  2. Provoque un fallo controlado.
  3. Conserve la evidencia.

Ventana de frescura declarada

Hacer explícito cuánto atraso puede tolerar cada lectura.

Problema que resuelve

Sin un límite declarado, una proyección aparentemente rápida puede entregar información inaceptablemente antigua.

Analogía

Como un boletín meteorológico: su utilidad depende de cuándo fue observado y cuándo se consulta.

Solución y contrato

Cada proyección publica última revisión aplicada, tiempo de actualización y límite contratado; el lector decide esperar, degradar o fallar.

si edad > ventana entonces esperar | degradar | fallar

Cuándo aplicarlo

Úselo en derivados asíncronos. Defina ventanas por decisión, no una cifra universal para todo el sistema.

Ejemplo ejecutable

Ejemplo pedagógico; no es una declaración de conformidad con Core 1.0. El consumidor acepta, espera o rechaza según la edad declarada.

Tablero de incendios forestales: Un tablero parece actual aunque la última proyección tenga dos horas.

Desde la raíz del repositorio, Node.js 22.13 o superior. La instalación requiere acceso al registro de paquetes.

Instalar y comprobar

npm ci --prefix replication
npm test --prefix replication/examples/patterns-r4

Resultado esperado: casos conformes y adversos de los treinta patrones y regresiones PC1 aprobados. El comando indica el conteo vigente. Los fragmentos usan tipos y ayudantes del proyecto completo.

TypeScript

export function ventanaFrescura(entrada: Entrada): Resultado {
  const generadoEn = fechaIso(texto(entrada, "generadoEn"));
  const consultadoEn = fechaIso(texto(entrada, "consultadoEn"));
  const maxMin = numero(entrada, "frescuraMaxMin");
  const edadMin = (consultadoEn - generadoEn) / 60_000;
  exigir(edadMin >= 0 && edadMin <= maxMin, "FRESHNESS_EXCEEDED", "La proyección excedió su ventana de frescura");
  return { edadMin, vigente: true };
}

{

Entrada adversa y rechazo o abstención esperados

    "consultadoEn": "2026-08-24T12:00:00Z",
    "frescuraMaxMin": 10
  },
  "codigoError": "FRESHNESS_EXCEEDED"
}

Alternativa más sencilla

Lectura canónica actual. Preferirla cuando el atraso permitido es cero.

Cuándo no usarlo

No adopte Ventana de frescura declarada si el problema no fue observado o una alternativa más simple satisface el contrato.

Costo que debe medir

Mida edad, percentiles de atraso e incumplimientos. Se conecta con Reconstrucción incremental y Frontera lectura-escritura.

Límite de esta demostración

La edad depende de relojes y tiempos de origen confiables.

Práctica guiada

Supere deliberadamente la ventana de frescura y verifique espera, degradación y fallo según contrato.

  1. Prepare un caso válido.
  2. Provoque un fallo controlado.
  3. Conserve la evidencia.

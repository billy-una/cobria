Identidad documental estable

Mantener una identidad independiente de ubicación, forma y proveedor.

Problema que resuelve

Claves derivadas de rutas, nombres visibles o posiciones cambian durante una migración y rompen referencias.

Analogía

Como el número de una muestra de campo: la etiqueta continúa aunque cambie de caja o estante.

Solución y contrato

Asigne una identidad opaca dentro del ámbito; trate claves externas como atributos versionados y valide colisiones en la frontera.

identidad = asignar(ámbito); referencias.usar(identidad)

Cuándo aplicarlo

Úselo cuando un documento sobreviva importaciones, fusiones o cambios de colección. Evite codificar significado mutable en la identidad.

Ejemplo ejecutable

Ejemplo pedagógico; no es una declaración de conformidad con Core 1.0. La identidad permanece estable mientras sus atributos pueden cambiar.

La misma cámara cambia de ubicación: Usar la ubicación como identificador crea otro dispositivo al moverla.

Desde la raíz del repositorio, Node.js 22.13 o superior. La instalación requiere acceso al registro de paquetes.

Instalar y comprobar

npm ci --prefix replication
npm test --prefix replication/examples/patterns-r4

Resultado esperado: casos conformes y adversos de los treinta patrones y regresiones PC1 aprobados. El comando indica el conteo vigente. Los fragmentos usan tipos y ayudantes del proyecto completo.

TypeScript

export function identidadEstable(entrada: Entrada): Resultado {
  const camaraId = texto(entrada, "camaraId");
  const ubicacionAnterior = texto(entrada, "ubicacionAnterior");
  const ubicacionNueva = texto(entrada, "ubicacionNueva");
  exigir(ubicacionAnterior !== ubicacionNueva, "NO_IDENTITY_CHANGE", "La prueba requiere un cambio de ubicación");
  return { camaraId, ubicacion: ubicacionNueva, identidadCambio: false };
}

Entrada conforme y resultado esperado

{
  "entrada": {
    "camaraId": "cam-0091",
    "ubicacionAnterior": "sendero-sur",
    "ubicacionNueva": "sendero-norte"
  },
  "esperado": {
    "camaraId": "cam-0091",
    "ubicacion": "sendero-norte",
    "identidadCambio": false
  }
}

Entrada adversa y rechazo o abstención esperados

{
  "entrada": {
    "camaraId": "cam-0091",
    "ubicacionAnterior": "sendero-norte",
    "ubicacionNueva": "sendero-norte"
  },
  "codigoError": "NO_IDENTITY_CHANGE"
}

Alternativa más sencilla

Identificador asignado por el motor. Usarlo si permanece estable al mover y renombrar.

Cuándo no usarlo

No adopte Identidad documental estable si el problema no fue observado o una alternativa más simple satisface el contrato.

Costo que debe medir

Mida colisiones, referencias huérfanas y tiempo de resolución. Se relaciona con Objeto canónico, Revisión obsoleta rechazada y Catálogo versionado.

Límite de esta demostración

Un ejemplo de cambio de ubicación no prueba unicidad global.

Práctica guiada

Cambie ubicación y nombre externo de diez documentos y demuestre que sus referencias internas permanecen válidas.

  1. Prepare un caso válido.
  2. Provoque un fallo controlado.
  3. Conserve la evidencia.

Cola de salida transaccional

Publicar cambios sin perder la relación entre escritura canónica y evento de integración.

Problema que resuelve

Guardar datos y publicar un mensaje son dos operaciones; una puede tener éxito y la otra fallar.

Analogía

Es preparar la carta dentro de la misma oficina donde se registra el trámite y enviarla después con acuse.

Solución y contrato

La transacción escribe entidad y registro de salida. Un publicador reintentable entrega el mensaje y marca progreso. Los consumidores permanecen idempotentes.

enUnaOperación { guardarCanónico(); guardarEventoSalida(); }

Cuándo aplicarlo

Úsela cuando el almacén no comparte transacción con el corredor. No la convierta en una cola sin retención, observabilidad o reparación.

Ejemplo ejecutable

Ejemplo pedagógico; no es una declaración de conformidad con Core 1.0. Prepara documento y evento en memoria; no ejecuta una transacción del motor.

Alerta por deslizamiento junto con la medición: Guardar la alerta después de la medición puede fallar y dejar el riesgo sin notificación.

Desde la raíz del repositorio, Node.js 22.13 o superior. La instalación requiere acceso al registro de paquetes.

Instalar y comprobar

npm ci --prefix replication
npm test --prefix replication/examples/patterns-r4

Resultado esperado: casos conformes y adversos de los treinta patrones y regresiones PC1 aprobados. El comando indica el conteo vigente. Los fragmentos usan tipos y ayudantes del proyecto completo.

TypeScript

export function colaSalidaTransaccional(entrada: Entrada): Resultado {
  const documentoId = texto(entrada, "documentoId");
  const eventoId = texto(entrada, "eventoId");
  exigir(entrada.mismaTransaccion === true, "OUTBOX_NOT_ATOMIC", "Documento y evento deben persistirse juntos");
  return { documentoId, outbox: { eventoId, estado: "pendiente" }, planCommit: "unico", persistido: false };
}

Entrada conforme y resultado esperado

{
  "entrada": {
    "documentoId": "sensor-8",
    "eventoId": "alerta-8",
    "mismaTransaccion": true
  },
  "esperado": {
    "planCommit": "unico",
    "persistido": false,
    "outbox": {
      "eventoId": "alerta-8",
      "estado": "pendiente"
    }
  }
}

Entrada adversa y rechazo o abstención esperados

{
  "entrada": {
    "documentoId": "sensor-8",
    "eventoId": "alerta-8",
    "mismaTransaccion": false
  },
  "codigoError": "OUTBOX_NOT_ATOMIC"
}

Alternativa más sencilla

Transacción nativa con bandeja de salida. Comprobar que documento y evento se confirman juntos.

Cuándo no usarlo

No adopte Cola de salida transaccional si el problema no fue observado o una alternativa más simple satisface el contrato.

Costo que debe medir

Mida retraso, reintentos, mensajes atascados y duplicados. Se relaciona con Proyección asíncrona y Punto de control.

Límite de esta demostración

La bandera mismaTransaccion es una precondición simulada, no una transacción.

Práctica guiada

Interrumpa el publicador después de guardar la entidad y confirme que el evento sigue recuperable.

  1. Prepare un caso válido.
  2. Provoque un fallo controlado.
  3. Conserve la evidencia.

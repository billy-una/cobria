Validación en frontera

Impedir que formas inválidas entren al núcleo documental.

Problema que resuelve

Aceptar primero y corregir después dispersa supuestos y convierte cada lector en un validador distinto.

Analogía

Como una estación biológica: cada muestra se registra y revisa antes de entrar al archivo.

Solución y contrato

La frontera comprueba forma, ámbito, revisión, vocabulario y reglas invariantes; devuelve errores estructurados sin escritura parcial.

validar(entrada, contrato, ámbito) o rechazarSinEfectos()

Cuándo aplicarlo

Aplíquelo en API, importadores, consumidores y herramientas. Conserve el dato crudo separado cuando sea evidencia legítima.

Ejemplo ejecutable

Ejemplo pedagógico; no es una declaración de conformidad con Core 1.0. Valida coordenadas y normaliza texto; la existencia de la especie en catálogo se comprueba aparte.

Formulario ciudadano de avistamientos: Coordenadas imposibles o especies desconocidas llegan hasta el almacén.

Desde la raíz del repositorio, Node.js 22.13 o superior. La instalación requiere acceso al registro de paquetes.

Instalar y comprobar

npm ci --prefix replication
npm test --prefix replication/examples/patterns-r4

Resultado esperado: casos conformes y adversos de los treinta patrones y regresiones PC1 aprobados. El comando indica el conteo vigente. Los fragmentos usan tipos y ayudantes del proyecto completo.

TypeScript

export function validacionFrontera(entrada: Entrada): Resultado {
  const latitud = numero(entrada, "latitud");
  const longitud = numero(entrada, "longitud");
  exigir(latitud >= -90 && latitud <= 90 && longitud >= -180 && longitud <= 180, "COORDINATES_INVALID", "Las coordenadas están fuera de rango");
  return { latitud, longitud, especie: texto(entrada, "especie").toLowerCase(), validada: true };
}

Entrada conforme y resultado esperado

{
  "entrada": {
    "latitud": 8.79,
    "longitud": -82.96,
    "especie": "TUCAN-PICO-IRIS"
  },
  "esperado": {
    "especie": "tucan-pico-iris",
    "validada": true
  }
}

Entrada adversa y rechazo o abstención esperados

{
  "entrada": {
    "latitud": 100,
    "longitud": -82.96,
    "especie": "tucan"
  },
  "codigoError": "COORDINATES_INVALID"
}

Alternativa más sencilla

Validador de esquema en frontera. Elegirlo si expresa todas las reglas necesarias.

Cuándo no usarlo

No adopte Validación en frontera si el problema no fue observado o una alternativa más simple satisface el contrato.

Costo que debe medir

Mida rechazos por causa, campos desconocidos y escrituras parciales. Se conecta con Contrato versionado y Herramienta de agente gobernada.

Límite de esta demostración

Validar coordenadas no verifica que la observación sea verdadera.

Práctica guiada

Diseñe cinco entradas inválidas y compruebe rechazo completo, causa legible y ausencia de efectos parciales.

  1. Prepare un caso válido.
  2. Provoque un fallo controlado.
  3. Conserve la evidencia.
